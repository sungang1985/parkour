# 《逼上梁山》游戏设计文档（GDD）

> 版本 0.1 · 类型：3D 无尽跑酷 · 平台：Android（竖屏），桌面可调试 · 引擎：Godot 4.7

## 1. 概述

**一句话**：风雪夜，林冲火烧草料场后杀出山神庙。身后是高俅派来的官兵，前方是八百里水泊梁山。玩家扮演梁山好汉一路狂奔，跳拒马、滚横幅、闪镖车、在岔路口急转，看谁能跑得最远。

| 项目 | 内容 |
| --- | --- |
| 玩法原型 | 《神庙逃亡》（Temple Run）的路口转弯 + 追兵机制，加上三车道换道 |
| 题材 | 《水浒传》：逼上梁山、风雪山神庙、野猪林、智取生辰纲、景阳冈打虎 |
| 单局时长 | 1～5 分钟 |
| 操作 | 单指滑动：↑跳 ↓滚 ←→换道 / 转弯 |
| 目标用户 | 喜欢轻度跑酷的手机玩家，对国风 / 水浒题材有好感的玩家 |
| 卖点 | 每个地域对应一回原著回目；好汉各有特长；锣鼓 + 五声音阶配乐 |

## 2. 引擎选型：Godot 4.7

结论：选 **Godot 4.7（当前最新稳定版）**，用 GDScript 开发，渲染器选 **Compatibility（OpenGL ES 3）**。

| 维度 | Godot 4.7 | Unity 6 |
| --- | --- | --- |
| 授权费用 | MIT 开源，永久免费，无分成、无安装费 | 个人版有收入门槛，超出需付费订阅 |
| 空项目安卓包体 | 约 25～35 MB | 约 20～40 MB（IL2CPP + 剥离后） |
| 安卓导出 | 编辑器内一键导出 APK / AAB | 成熟，需要 Unity Hub + 模块 |
| 迭代速度 | 编辑器约 100 MB，秒开；GDScript 改完即跑 | 编辑器数 GB，C# 编译等待较长 |
| 版本管理 | 场景 / 资源是纯文本，合并友好 | 场景是 YAML，合并较痛苦 |
| 生态 | 资源商店较小 | 资源商店、插件、SDK 最丰富 |

对这款**单人 / 小团队、3D 低多边形、不依赖大量商业插件**的跑酷游戏，Godot 的零授权成本、小体积和快速迭代最实用。如果后期必须接入大量商业广告 / 统计 SDK 且团队已熟悉 C#，再考虑 Unity。

渲染器选 Compatibility 的原因：兼容 OpenGL ES 3.0 的老旧安卓机（覆盖面最广），本作的低多边形 + 雾效画风不需要 Vulkan 的高级特性。

## 3. 世界观与故事

- **主线**：林冲遭高俅陷害刺配沧州，在草料场被陆谦纵火暗算。风雪夜他在山神庙手刃仇人，从此走投无路，只能投奔梁山。游戏从“山神庙”出发，玩家的终极目标是“奔向梁山”。
- **追兵**：高俅派出的官兵（红衣铁盔、手持火把长枪）紧追不舍，对应《神庙逃亡》里的恶魔猴子。
- **地域即章节**：每跑约 700 米进入一个新地域，屏幕上浮现该地名和对应的原著回目，形成“一路跑过水浒故事”的体验。

| --- | --- | --- | --- | --- |
| 1 | 山神庙 | 第十回 林教头风雪山神庙 陆虞候火烧草料场 | 雪夜青灰石路、红墙庙宇、燃烧的草料堆、飘雪 | 灯笼、雪松、“缉拿要犯”横幅 |
| 2 | 野猪林 | 第八回 林教头刺配沧州道 鲁智深大闹野猪林 | 浓雾密林、泥土路 | 倒木、巨石、“野猪林”横幅 |

| 4 | 景阳冈 | 第二十三回 横海郡柴进留宾 景阳冈武松打虎 | 夕阳红叶、落叶纷飞 | “三碗不过冈”酒旗、“冈上有虎”告示牌 |

## 4. 核心玩法

### 4.1 操作

| 操作 | 触屏 | 键盘（调试） | 效果 |
| --- | --- | --- | --- |
| 跳跃 | 上滑 | ↑ / W / 空格 | 越过拒马、倒木、断路、酒坛 |
| 翻滚 | 下滑 | ↓ / S | 从横幅下钻过；空中下滑可急降 |
| 换道 | 左右滑 | ← → / A D | 在三条道之间切换 |
| 转弯 | 路口前左右滑 | 同上 | 在路口处转向，可提前输入 |
| 暂停 | 右上角按钮 | Esc / P | 安卓返回键同样暂停 |

滑动识别在手指移动超过屏幕短边 5% 时立即触发，不必等抬手，响应更快。

### 4.2 规则

- **自动前进**：速度从 11 米/秒平滑上升到约 27 米/秒（`speed = 11 + 16 × (1 − e^(−路程/2200))`）。
- **跳跃 / 翻滚时长随速度缩短**（× √(11/速度)），保证高速时跳跃的水平距离不会过长、仍有反应空间。
- **路口**：向北跑时遇到 T 字路口（左右都能转），向东或向西跑时遇到 L 形弯（只能转回北）。错过路口就会撞墙（或跌进水里）。
- **绊倒与追兵**：撞上酒坛或换道时侧面擦到障碍会“绊一跤”：短暂减速，官兵追到身后；7 秒内再绊一次即被擒。
- **致命**：正面撞上拒马 / 横幅 / 镖车 / 官兵，掉进断路，错过路口。
- **计分**：每跑 1 米得 1 分，每枚铜钱 10 分；“替天行道”旗生效时得分翻倍。

### 4.3 障碍

| 障碍 | 水浒元素 | 应对 | 判定体积（宽 × 高 × 深，米） |
| --- | --- | --- | --- |
| 拒马 / 倒木 | 官府路障、野猪林倒木 | 跳 | 整路或单道 × 0.9 × 0.7 |
| 横幅 | “缉拿要犯”“三碗不过冈”“替天行道” | 滚 | 下沿 1.15 米，高 1.3 |
| 镖车 / 巨石 / 持盾官兵 | 生辰纲、景阳冈 | 换道 | 单道 × 3.2 × 2.2（跳不过去） |
| 断路 / 断桥 | 山道塌方、栈道断板 | 跳 | 整路 × 2.4 深（视觉 3 米） |
| 酒坛 | “三碗不过冈” | 跳或换道 | 单道 × 0.8；撞到只绊倒不致命 |
| 路口尽头 | 庙墙“此路不通” / 湖面 | 转弯 | — |

玩家碰撞盒：站立 0.7 × 1.7 × 0.6，翻滚 0.7 × 0.8 × 0.6，跳跃高度 1.6 米。

**生成规则**：每 12 米一段路有两个障碍槽位，相邻两行障碍至少间隔 `max(11, 速度 × 0.95)` 米；出生后 40 米、每个路口前一段、转弯后的两段“预览路”都不放障碍。难度（0→1，约 2.5 公里满）提高障碍出现率，并逐步加入“双道阻挡”“三道混合”这类组合。任何一行都保证至少有一条可通过的车道。

## 5. 经济与成长

- **铜钱**：赛道上成串出现；绕开镖车，越过拒马 / 断路 / 酒坛时拱成弧线（引导跳跃），横幅下压低（引导翻滚）。
- **消耗**：解锁好汉；**续命**（每局最多 3 次，100 / 200 / 400 铜钱，复活后清空前方 30 米并无敌 2.5 秒）。
- **记录**：最高分、最远距离、总局数存于 `user://save.cfg`。

## 6. 美术与音频

- **画风**：低多边形 + 远景雾（“水墨留白”感），朱红、金、宣纸色的界面；标题与牌匾使用毛笔楷书（马善政体），正文用思源黑体。
- **场景物件**：全部由立方体、圆柱、圆锥、球、棱柱拼成，网格和材质全局共享，零外部美术资源即可运行；后续可逐个替换为 glTF 模型。
- **音频**：全部程序合成，无音频素材。
  - 音效：铜钱“叮”、跳跃、翻滚、转弯、绊倒、撞击、坠落、开局锣鼓。
  - 配乐：D 宫调五声音阶（宫商角徵羽）的拨弦旋律（Karplus-Strong 算法模拟古筝），配战鼓和梆子，后台线程合成约 19 秒无缝循环。

### 7.2 赛道生成：为什么永远不会自相交

赛道朝 北 / 东 / 西 三个方向延伸，从不向南：

- 向北时生成 **T 字路口**，左右两侧各先放 2 段无障碍“预览路”；
- 向东 / 西时生成 **L 形弯**，只能转回北。

因此每条东西向路段都在不同的“纬度”上，彼此之间至少隔着一整段北向路（≥ 84 米），路边装饰（单侧 ≤ 26 米）也不会重叠。生成器最多生成到下一个路口为止；玩家转弯后删除另一侧预览路，再沿所选方向继续生成。身后 30 米外的路段即时释放，场景中同时存在的路段约 12～15 段。

### 7.3 玩家运动模型

玩家不用物理刚体，而是记录“路段起点 + 前进方向 + 沿路距离 s + 横向偏移 + 高度 y”，每个物理帧计算世界坐标。转弯时把当前世界坐标投影到新路段坐标系（新的 s 和横向偏移），位置完全连续，再把横向偏移平滑拉回中道，相机和人物朝向同时平滑转动。

碰撞用 `Area3D`：玩家 1 个碰撞盒（翻滚时缩矮），障碍（层 2）和拾取物（层 4）只开 `monitorable`，大幅降低物理开销。开启**物理插值**，所有运动都在 `_physics_process` 中进行，60Hz 物理在 90 / 120Hz 屏幕上依然顺滑。

### 7.4 性能预算（中端安卓机）

| 项 | 预算 |
| --- | --- |
| 帧率 | 60 FPS |
| 同屏绘制调用 | ≤ 400（实测 110～285，见下） |
| 同屏碰撞体 | ≤ 150 |
| 包体 | ≤ 40 MB |
| 内存 | ≤ 250 MB |

实测（自检截图模式，540×960）：跑动中每帧绘制调用 146～229、可见物体 157～240；
结算界面叠加 UI 时约 280。长跑 150 秒场景节点峰值约 1450 个，路段回收及时，不随路程增长。

后续优化方向：路边装饰改用 `MultiMeshInstance3D` 合批；对象池复用路段节点。

## 8. 测试

- `godot --headless --fixed-fps 60 -- --selftest`：约 10 秒跑完 450 秒的模拟游戏时间，校验
  不操作会出局、结算 / 续命流程、3 个随机种子下自动驾驶各跑 150 秒（约 2500 米、20+ 次转弯）、转弯时位置无瞬移、经过多个地域、存档 / 解锁。
- `-- --selftest --shots=<目录>`（需显示环境）：自动截取主菜单、结算、每个地域、路口的画面。
- 真机：用 Godot 的一键部署（Remote Debug）安装到手机，检查滑动手感和帧率。
